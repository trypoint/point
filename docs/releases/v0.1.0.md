# Point Framework v0.1.0 — release notes

**Status: v0.1.0 publication approved on 2026-11-28; real-host production validation explicitly deferred for this version.** Publication is not evidence that a specific production environment was validated.

## Overview

Point is a lightweight PSR-compatible PHP microframework. This release candidate sets the runtime version to `0.1.0` and targets PHP `>=8.4.27`. CI validates PHP 8.4.27, PHP 8.4, and PHP 8.5 on Ubuntu; PHP 8.4 and PHP 8.5 on Windows; and an Ubuntu Nginx/PHP-FPM fixture. These CI fixtures do not certify a production server or proxy topology.

Install after publication with:

```bash
composer require trypoint/point:^0.1
```

The package includes HttpSoft as its PSR-7/PSR-17 fallback. Optional complete providers include Nyholm, Laminas Diactoros, and Guzzle PSR-7. Runtime dependencies are listed in the package's `composer.json` and remain unchanged from RC.1.

## Changes

- Simplify test-suite navigation and developer documentation; retain all 283 tests and archive historical Alpha/Beta/RC reports.
- Retain `LICENSE` as the single MIT license file, removing duplicate `LICENSE.md`; preserve the Slim migration guide in Composer archives.

- XML exception responses preserve dynamic titles containing XML markup characters and Unicode while producing valid XML.
- XML request parsing restores the previous libxml error mode on success and failure.
- Release documentation clarifies supported PHP versions, the approved API compatibility policy, and deployment trust boundaries.

## Compatibility and security

The maintainer approved the full v0.1.0 API Freeze on 2026-11-28, including the provisional, behavior-compatible status of `HttpDefinitions`, `PointDefinitions` and `PipelineRunner` and the approved member-level exceptions. The PHP-CS-Fixer global baseline exception is accepted for v0.1.0 only and remains reported as FAIL. See the [API freeze approval record](../architecture/STABLE-0.1.0-API-FREEZE.md) and [security/readiness gates](../architecture/STABLE-0.1.0-RELEASE-READINESS.md).

Set request-body limits at a trusted ingress before enabling JSON, form, or XML parsing. Validate Host and forwarded headers at a trusted proxy and restrict direct backend access. Production deployment configurations and the actual production TLS/proxy topology have not been independently validated. On 2026-11-28 the maintainer explicitly deferred the **real-host validation requirement for this library release only**; every live-host checklist item remains NOT RUN, not PASS. Each consuming application must validate these controls for its actual hosting setup. The maintainer authorized completion of v0.1.0 on 2026-11-28. GitHub tag, Release and Packagist publication must still be verified independently; approval does not mean they have happened.
